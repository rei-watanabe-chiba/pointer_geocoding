## 人手確認チェックリスト

### 確認手順

1. **StartDialogでの新規セッション作成・設定保存・読込（D-2の影響確認）**
   1. QGISでプラグインを起動し、StartDialogを開く。
   2. 「新規セッション」を選択した状態で、親フォルダとセッション名、測量グリッドの原点・数を入力し「OK」で確定する。
   3. セッションフォルダが生成され、メイン操作パネル（QDockWidget）が起動することを確認する。
   4. Tab3（設定）で任意の設定値（例: 基準点シンボルサイズ、線色など）を変更し「適用」ボタンを押す。
   5. QGISを一度終了し、同じセッションフォルダを「既存セッション」として再度開く。
   6. Tab3の設定値が、手順4で変更した値のまま復元されていることを確認する。

2. **Tab1での座標変換（execute_transformation経由、D-1の影響確認）**
   1. Tab1で画像を新規追加し、レイヤ名を入力して「確定」する。
   2. プレビューダイアログ上で2点以上の基準点をクリックし、グリッド入力ダイアログで実座標を割り当てる。
   3. 「座標変換」を実行し、残差（回転角・縦横比）が表示されることを確認する。
   4. 「レイヤ出力」を実行し、画像がメインキャンバス上の正しい位置に再配置されることを確認する。

3. **Tab2での打刻によるGeoPackage書き込み（update_point_layer_geometryが使われる画像再変換時の点群追従、D-1の影響確認）**
   1. 手順2で座標変換・レイヤ出力を行った画像に対し、Tab2で複数の遺物点を打刻する（出土形態・遺構名・属性・点名等を入力）。
   2. Tab1に戻り、同じ画像（レイヤ）を編集削除モードで選択し、基準点位置を変更するか新たな基準点構成で再度「座標変換」→「レイヤ出力」を実行する。
   3. 手順1で打刻した既存の遺物点群が、画像の新しい位置に自動追従して移動することを確認する（点群がずれたまま取り残されていないこと）。
   4. Tab2で該当点を選択し、属性フォームに読み込まれる `real_x`/`real_y` の値が、画像の新しい位置と整合していることを確認する。

4. **Tab3での設定変更→適用（D-2の影響確認）**
   1. Tab3で基準点・遺物点のサイズ/線幅/線色/塗り有無、ラベルのサイズ/配置間隔/白線有無、大・小グリッドの表示縮尺のいずれかを変更する。
   2. 「適用」ボタンを押し、キャンバス上のシンボロジ・ラベル表示が即座に更新されることを確認する。
   3. QGISプロジェクトを保存せずに一度Tab1やTab2に切り替え、再度Tab3に戻っても変更後の値が保持されていることを確認する。

5. **意図的にエラーを発生させた場合のエラーダイアログ表示（D-3の影響確認）**
   1. StartDialogで「新規セッション」を選択したまま、親フォルダ欄を空欄にして「OK」を押し、警告ダイアログ（フォルダ未入力）が表示されることを確認する。
   2. StartDialogでセッション名に使用不可文字（例: `\` や `/` 等）を入力して「OK」を押し、警告ダイアログ（セッション名不正）が表示されることを確認する。
   3. Tab1のプレビューで基準点を2点だけ選び、両基準点の図面上座標または実座標を同一点にした状態で「座標変換」を実行し、エラーダイアログ（計算エラー：ヘルマート変換パラメータ算出不可）が表示されることを確認する。
   4. Tab1で基準点を3点未満（0点または1点）の状態で「座標変換」を実行し、エラーダイアログ（基準点数不足）が表示されることを確認する。
   5. Tab2で実座標が未取得（`real_x`/`real_y` が NULL）の打刻点が存在する状態でCSV出力を実行し、警告ダイアログ（座標未取得エラー）が表示されることを確認する。
   6. いずれのダイアログも、タイトル・本文の文言が従来と変わっていないこと（例: 「計算エラー」「座標変換には最低2点以上の基準点が必要です。」等）を確認する。

### 各手順で期待される挙動（設計書ベース）
- 手順1: `docs/integrated_master_design.md` 2.1節「セッション起動とプロジェクト構築」および2.4節「Tab 3: 設定と動的シンボロジ更新」の「設定の永続化: `settings.json` をセッションごとに保持し、次回起動時にも前回の設定状態を復元する」に基づき、新規セッション作成時にメインパネルが起動し、Tab3で保存した設定が次回起動時も復元されるべき。
- 手順2: 同ドキュメント2.2節「Tab 1: 画像管理と事前ジオリファレンス」の「『座標変換』を実行して残差を確認し、『レイヤ出力』で画像（ワールドファイル更新）をメインキャンバスへ再配置」に基づき、座標変換パラメータの算出とレイヤ出力が正しく行われるべき。
- 手順3: 同ドキュメント2.2節「同時に、その画像に紐づく過去の打刻点群も自動で新しい位置へ追従移動」、および2.3節「打刻時はキャンバス座標を実空間座標 (`real_x`, `real_y`) としてGeoPackageに追加するだけでなく、対象図面のローカル座標 (`pixel_x`, `pixel_y`) も…算出して併せて保存する。これにより画像再変換時の点群自動追従を実現する」に基づき、`update_point_layer_geometry`（今回D-1でリファクタ）経由で点群がGeoPackageに正しく書き込まれ、追従移動するべき。
- 手順4: 同ドキュメント2.4節「各項目を調整し『適用』ボタンを押すと、即座にキャンバス上のすべてのレイヤの見た目が更新される」「`settings.json` をセッションごとに保持し…前回の設定状態を復元する」に基づき、設定変更が即座に反映され、かつ永続化されるべき。
- 手順5: 同ドキュメント1章のモジュール一覧における `transform.py`（座標変換モジュール…点群の追従再配置ロジック）および `start_dialog.py` の入力検証責務、ならびに今回のD-3変更（`QMessageBox.critical/warning` を `UIStyleHelper.show_error_dialog`/`show_warning_dialog` に置換、文言は無変更）に基づき、エラー/警告条件に該当した場合、従来通りのタイトル・文言でダイアログが表示されるべき。

### 注意喚起
- 今回の変更で最も影響範囲が広いのは `src/core_logic.py` の `update_point_layer_geometry()`（D-1）である。Tab1での「座標変換」実行時（新規点なし）だけでなく、**Tab2で打刻した点群がある状態でTab1から画像を再変換した場合**の点群追従が主な影響対象であり、上記手順3で重点的に確認すること。
- `src/transform.py` の `execute_transformation()` 内、基準点レイヤの `target_x`/`target_y` 更新も同様にD-1の影響を受ける。基準点を複数回設定し直した際に、古い基準点の `target_x`/`target_y` が正しく上書きされているか（Tab1のプレビューダイアログ再表示時に反映されるか）を合わせて確認するとよい。
- `src/settings_metadata_mixin.py`（D-2）は `settings.json` と `image_metadata.json` の両方の読み書きに関わる。settings.json破損時（手動で不正なJSONを書き込んだ場合など）にデフォルト設定へフォールバックする挙動、および `image_metadata.json` が存在しない新規セッションでの画像追加・座標変換・メタデータ保存が問題なく行われるかも、時間があれば確認することが望ましい。
- `src/style_helper.py` の `show_error_dialog`/`show_warning_dialog`（D-3）はメッセージボックスの文言・タイトルを変更していないため、表示テキスト自体に差異が出ることは想定していないが、`transform.py` の計10箇所・`start_dialog.py` の6箇所すべてを置き換えているため、上記手順5以外のエラーパス（例: CSV書き込み権限エラー、アフィン変換で3点が同一直線上にある場合等）についても、余裕があれば個別に発生させて文言が変わっていないか確認すると安心である。
