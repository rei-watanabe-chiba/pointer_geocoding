## 人手確認チェックリスト

対象タスク: Stage B main_dock.py のMixinベース分割（`.claude/logs/implement/2026-09-14-stageB-main-dock-mixin-split.md` 参照）

### 確認手順

1. QGIS（3.22〜3.99の対象バージョン環境）でプラグイン `pointer_geocoding` を再読み込み（プラグインリロード、またはQGIS再起動）し、プラグインを有効化する。QGISのPythonコンソール／ログパネルにエラー（特に `ImportError` / `AttributeError` / `ModuleNotFoundError`）が出力されないことを確認する。
2. StartDialog から新規セッションを作成し（または既存セッションを開き）、メイン操作パネル（`MainDockWidget`、QDockWidget）が正常に表示されることを確認する。
3. Tab1「画像管理」を開き、以下を順に行う。
   1. 画像ファイルを「参照...」で選択し、レイヤ名を入力して「確定」をクリックする。
   2. プレビューダイアログが起動し、「基準点設定」からプレビュー画像上をクリックして基準点（最低2点、最大4点）をグリッド入力ダイアログ（GridInputDialog）で登録する。
   3. 「座標変換」を実行し、残差（回転角度・アスペクト比）が表示されることを確認する。
   4. 「レイヤ出力」を実行し、ワールドファイルが生成されメインキャンバスに画像が配置されること、および自動的にTab2「遺物点作成」へ切り替わることを確認する。
4. Tab1の「編集削除」モードに切り替え、既存レイヤ（手順3で作成したもの）をセレクタで選択し、レイヤ名のリネーム、基準点の再編集、「レイヤ削除」による削除がそれぞれ正常に行えることを確認する。
5. Tab2「遺物点作成」を開き、以下を順に行う。
   1. 出土形態（グリッド／遺構）・属性等を設定し、メインキャンバス上をクリックして打刻する。点が登録され、点名が自動インクリメントされることを確認する。
   2. 既存の打刻点にマウスを近づけてホバー時のハイライトを確認し、クリックして属性値がフォームにロードされること、編集・削除（「削除」ボタン）が行えることを確認する。
   3. 「フォーカスモード」をON/OFFし、対象外透明度のスライダーを操作して、対象図面・出土形態・遺構名・属性でフィルタされた点群の表示濃淡が切り替わることを確認する。
   4. 「CSV出力」で、出土形態・遺構名・属性・点名・枝番・X座標・Y座標の7項目でCSVが出力されることを確認する。
6. Tab3「設定」を開き、基準点／遺物点のサイズ・線幅・線色・塗り有無、ラベルのサイズ・間隔・白線有無、大小グリッド表示縮尺を変更して「適用」をクリックし、メインキャンバス上のシンボロジ（基準点・打刻点・ラベル）が即座に更新されることを確認する。
7. 上記2〜6の一連の操作中、QGISが例外ダイアログを出したりクラッシュしたりしないことを確認する。

### 各手順で期待される挙動（設計書ベース）

- 手順1: `docs/integrated_master_design.md` §1.4 の `main_dock.py` の記述の通り、`MainDockWidget`は`Tab1GeorefMixin`・`Tab2DigitizingMixin`・`Tab3SettingsMixin`を多重継承して構成される。これらのMixinが正しくimportされ、プラグインロード時に`ImportError`等が発生しないことは、本分割作業の前提条件である。
- 手順2: §2.1「セッション起動とプロジェクト構築」の記述の通り、確定後にセッションフォルダが自動生成され、メイン操作パネルが起動する。
- 手順3: §2.2「Tab 1: 画像管理と事前ジオリファレンス」の記述の通り、新規追加モードで画像を確定→基準点設定→座標変換（2点ヘルマート/3点以上アフィン）→レイヤ出力（ワールドファイル生成・メインキャンバス再配置・Tab2への自動遷移）という一連の流れが成立する。今回の分割ではこれらの処理はすべて`tab1_georef_mixin.py`の`Tab1GeorefMixin`に移動しているため、Mixin合成が正しく機能しているかの確認になる。
- 手順4: §2.2 の記述の通り、編集削除モードでは「確定」でリネーム（ファイル・QGISレイヤ・点群属性の連動）、「レイヤ削除」で紐づく点群をグローバル化した上での安全な削除が行われる。
- 手順5: §2.3「Tab 2: 遺物点作成・連続打刻とCSV出力」の記述の通り、打刻時はCanvasDigitizingToolから`canvas_clicked`シグナルでキャンバス座標のみが通知され、入力検証・重複チェック・フィーチャ組み立て・GeoPackage書き込みは`main_dock.py`側（今回の分割後は`tab2_digitizing_mixin.py`の`Tab2DigitizingMixin._on_canvas_clicked()`）が行う。既存点のホバー判定・選択・フォーカスモードのフィルタ条件プッシュ（`update_focus_state()`）も同様にこのMixinに属する。CSV出力は7項目にスリム化された形式で出力される。
- 手順6: §2.4「Tab 3: 設定と動的シンボロジ更新」の記述の通り、「適用」ボタン押下でLayerManagerに設定が保存され、`settings_changed`シグナル経由で`_on_layer_manager_settings_changed()`（今回の分割後は`tab3_settings_mixin.py`の`Tab3SettingsMixin`に配置）が基準点・打刻点シンボロジの再適用とキャンバス再描画を行う。

### 注意喚起

- 今回の変更は**ロジックを一切変更しない機械的なファイル分割**であるため、コードの実行時の振る舞い自体は変わらない想定である。ただし、以下の点は分割特有のリスクとして重点的に確認してほしい。
  - **多重継承(MRO)によるメソッド解決の正しさ**: `MainDockWidget(QDockWidget, Tab1GeorefMixin, Tab2DigitizingMixin, Tab3SettingsMixin)` の構成で、各Mixinのメソッド（例: `_create_tab1_ui`, `_create_tab2_ui`, `_create_tab3_ui` 等）が期待通りに解決されているか。今回のメソッド名にMixin間の重複はない設計だが、実行時のAttributeErrorが起きないことをQGIS上で確認する必要がある。
  - **`main_dock.py`から`UIConfig`を`main_dock_constants.py`経由で再exportしている点**: `src/layer_manager.py` と `src/map_tool.py` が実行時に `from .main_dock import UIConfig` を行っている（本タスクのスコープ外ファイルだが依存関係として存在）。この依存が壊れていないかは、特に基準点シンボロジ適用処理（Tab3の「適用」、および基準点プレビュー画面でのマーカー表示）で顕在化しやすいため、当該箇所の動作は注意して確認すること。
  - **循環import**: `main_dock_constants.py` と `main_dock_dialogs.py` は `main_dock.py` や各Tab Mixinに依存しない設計にしたが、QGIS実行環境でのプラグイン起動シーケンス（`plugin.py` → `main_dock.py` → 各Mixin/定数/ダイアログモジュール）でimportエラーが起きないかは、実際にQGISを起動して初めて確定的に確認できる。
  - **`update_symbology_opacity`の共有**: Tab2のフォーカスモードトグル・スライダー解除時と、Tab3の設定変更反映時の両方から呼び出される共有メソッドとして`main_dock.py`本体に意図的に残置した。Tab2操作後・Tab3操作後の両方でシンボロジが正しく更新されるか、双方の経路を必ず確認すること。
