## 人手確認チェックリスト

本タスクは `to_excel_column` / `from_excel_column` という2つの純粋関数（QGIS APIに依存しない文字列⇔数値変換ロジック）を
`src/layer_manager.py` / `src/start_dialog.py` から `src/core_logic.py` へ移動し、呼び出し元を差し替えたのみであり、
ロジック自体は一切変更していない（実装ログの自動テスト実行結果に記載の通り、移植前後のアサーション一致を確認済み）。
そのため本来QGIS上での実動作確認は不要と判断できるが、プロジェクトの方針（実行環境依存の確認項目「有り」）に従い、
影響を受ける2つのUI機能（グリッド座標プレビュー、グリッドCSV生成）について確認手順を残す。

### 確認手順
1. QGISでプラグイン「点群座標取得」を起動し、StartDialog で「新規セッション」を選択する。
2. StartDialog 内のグリッド設定エリアで、プレビュー用の大グリッドY欄（列アルファベット、例: `C`）とX欄（数値、例: `152`）に値を入力し、原点・範囲を設定した状態でプレビュー表示（`{gx}{display_y}-00座標: X: ..., Y: ...` あるいは `範囲外`）が表示されることを確認する。
3. 手順2で、列アルファベットとして `AA` のような2文字の入力を行い、範囲内であれば座標が、範囲外であれば赤色の「範囲外」表示が出ることを確認する。
4. 新規セッションを確定し、メイン操作パネルが起動した後、セッションフォルダ内に `PointGeo_grid.csv` が生成されていることを確認し、その内容（1列目: 大グリッドX数値, 2列目: 大グリッドYアルファベット, 3列目: 小グリッド番号, 4/5列目: 座標）が、大グリッドYが `A, B, ..., Z, AA, AB, ...` の順でアルファベット表記になっていることを確認する。
5. 既存セッションを開く際、CSVインポート処理（`start_dialog.py` の既存メタデータCSV読み込み、`from_excel_column` 呼び出し箇所）を通るケース（既存の `PointGeo_grid.csv` を伴うセッションフォルダを親フォルダとして選択）で、StartDialogの各スピンボックス・テキスト欄（原点X/Y、範囲X/Y）に既存CSVのメタデータ（大グリッドYの最大アルファベット等から算出した range_y 等）が正しく反映されることを確認する。

### 各手順で期待される挙動（設計書ベース）
- 手順2, 3: `docs/integrated_master_design.md` 2.1節「グリッド座標プレビュー」に「入力されたプレビュー名（例: 152C）からリアルタイムに座標を計算（1大グリッド=40m間隔）。範囲外の場合は赤色のエラー表示。」との記載があり、アルファベット列（`C`, `AA`等）から数値への変換（`from_excel_column`）が正しく行われることが前提の挙動である。
- 手順4: `docs/integrated_master_design.md` の構成図（53行目付近）に `PointGeo_grid.csv ← 測量系グリッド座標データ` との記載があり、`layer_manager.py` の `generate_grid_csv`（`to_excel_column` を使用して大グリッドYのアルファベット表記を生成）によって出力されるファイルである。
- 手順5: `docs/integrated_master_design.md` 2.1節「CSVデータのメモリキャッシュ: 対象グリッドCSVを読み込み、座標変換用辞書をメモリにキャッシュ。」との記載に基づき、既存セッションのCSVメタデータ読み込み時に `from_excel_column`（旧 `self.from_excel_column`）が正しく動作する必要がある。

### 注意喚起
- 今回の変更は関数の移動と呼び出し元の差し替えのみであり、アルゴリズム自体（`n<=0` で空文字列を返す、非アルファベット文字列で `0` を返す等のエッジケース挙動を含む）は変更していない。そのため、既存の挙動から差異が生じる可能性は低いと考えられるが、静的検証（本エージェントによるコード確認）では実行時の呼び出し経路（import解決、循環importの有無等）までは保証できないため、QGIS上でのプラグイン起動確認は必須とする。
- 特に `src/start_dialog.py` は `from .core_logic import from_excel_column` を新規に追加している。`core_logic.py` は `qgis.core` / `qgis.PyQt.QtCore` をトップレベルでimportしているため、QGIS実行環境外（本エージェントの静的検証環境）ではこのモジュールの実行時importの正当性を検証できていない。QGIS上でStartDialogが正常に開くこと（import エラーが発生しないこと）を必ず確認すること。
- `src/layer_manager.py` は元々 `core_logic` から `from_survey_coords` / `to_survey_coords` を既にimportしていたため、`to_excel_column` の追加importによる新規のimportリスクは低いと考えられるが、念のため手順4のグリッドCSV生成が正常に行われることを確認すること。
