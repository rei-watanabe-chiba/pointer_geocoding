## 人手確認チェックリスト

### 確認手順
1. QGISで本プラグインを起動し、起動時ダイアログ（`start_dialog.py`）を開く。グリッド設定関連のQSpinBox群（列数・行数など）を目視し、続けて各スピンボックスの上矢印ボタン・下矢印ボタンをそれぞれクリックして値が増減することを確認する。
2. tab2（PLOT画面）で編集モードに入り、点名スピンボックス（`edit_point_name`）を表示させる。上矢印・下矢印ボタンをクリックし、値が増減すること、また矢印の見た目が潰れていないことを確認する。
3. tab3（設定タブ）等、他にQSpinBoxが存在する画面があれば同様に矢印表示・クリック動作を確認する（`dialogs.py`内のスピンボックス使用箇所を含む）。
4. QGISのテーマ（ライト/ダーク、OSのテーマ設定）を変えられる場合は、それぞれのテーマでも矢印表示が崩れないか確認する。

### 各手順で期待される挙動（設計書ベース）
- 手順1: `docs/integrated_master_design.md`にQSpinBoxへのQSS適用を原則禁止する記述があり、その背景はT-0041で`::up-arrow`/`::down-arrow`を独自ハックで上書きしたことによるOS標準矢印描画の破壊（start_dialog.pyでの矢印消失）であった。今回はarrowサブコントロールに一切のルールを追加していないため、start_dialog.pyのグリッド設定スピンボックス群でOS標準の矢印が表示され、クリックで値が増減することが期待される（＝T-0041の回帰が再発していないこと）。
- 手順2: 同様の理由により、tab2の`edit_point_name`でも矢印が表示・クリック動作することが期待される。
- 手順3: `QSpinBox`ルールはグローバルQSS（`get_style_sheet()`）経由で全画面に適用されるため、他のQSpinBox使用箇所でも同様の挙動が期待される。
- 手順4: `QSpinBox`ルールは`palette(base)`/`palette(mid)`/`palette(highlight)`等のQtパレットロール参照のみを用いており、既存のQLineEdit/QComboBoxと同じテーマ非依存方式のため、ライト/ダーク双方で崩れないことが期待される（矢印の色自体はQtベーススタイル依存のため、QSS側では保証していない）。

### 注意喚起
- 今回の変更は`UIStyleHelper.get_style_sheet()`にルールを追加しただけだが、QSSはプラグイン全体にグローバル適用されるため、影響範囲はQSpinBoxを使用する全画面（start_dialog.py, tab2_plot.py, tab3_settings.py, dialogs.py）に及ぶ。
- `QSpinBox::up-button, QSpinBox::down-button`に`width: 18px`を指定しており、矢印グリフ自体はプラットフォーム依存で描画されるため、環境（Windows/Linux/macOSやQtスタイル設定）によって見え方に差が出る可能性がある。特に「矢印がつぶれて見える」問題が改善したかどうかは、実機のOS/Qtスタイル環境での目視確認が必須。
- `min-width: 70px`を新規追加したため、既存レイアウト（`build_flex_row`のストレッチ比率で幅が絞られている箇所）でスピンボックスが必要以上に横幅を取り、隣接ウィジェットが窮屈にならないか、あわせて目視確認すること。

### 4回目のフォローアップ確認項目（2026-09-16、base64データURI→実ファイルSVG参照への転換分）

3回目のフォローアップで採用したbase64データURI方式が、矢印が完全に非表示になる（QTBUG-51081によるQtのbase64データURI読み込み制限）という結果になったため、実ファイルSVG（`src/icon/spin_up_arrow.svg`/`spin_down_arrow.svg`）への絶対パス参照方式へ転換した修正の追加確認項目。上記の手順1〜4を再度実施する際、以下の点も併せて確認すること。

1. **最優先**: start_dialog.py・tab2_plot.py（`edit_point_name`）・その他QSpinBox使用箇所の全てで、上ボタン内・下ボタン内に**三角形の矢印グリフが表示されていること**（3回目のフォローアップ時点で再発していた「矢印が完全に非表示」状態になっていないこと）。
2. QGISプラグイン起動時に、アイコンファイル（`src/icon/spin_up_arrow.svg`/`spin_down_arrow.svg`）のパス解決に起因するエラーダイアログ・コンソールエラー（`ImportError`、ファイル未検出警告等）が出ていないこと。特に、プラグインがZIP配布されている場合や、インストール先ディレクトリ構成が開発時と異なる場合に、`os.path.dirname(os.path.dirname(os.path.abspath(__file__)))`によるパス計算がずれていないか（アイコンが表示されない場合はこの可能性を疑うこと）。
3. 矢印の色は引き続きニュートラルグレー（`#6B6B6B`固定、テーマ非追従）であること（3回目のフォローアップから仕様変更はない）。
4. 矢印画像のサイズ（8x6px相当）がボタン領域内に収まっており、ボタン外へのはみ出しや、テキスト入力領域への重なりがないこと。

期待される挙動の根拠: 本項目は`.claude/logs/implement/2026-09-16-T-0044-qspinbox-safe-qss.md`の「4回目のフォローアップ修正」セクションに記載の通り、`QSpinBox::up-arrow`/`QSpinBox::down-arrow`の`image`プロパティ参照先を、Qtで既知の制限があるbase64データURIから、`src/icon/`配下の実SVGファイルへの絶対パス参照（既存の`image.svg`/`setting.svg`等と同じurl()参照方式）へ切り替えたことによる。

### 押下フィードバック追加の確認項目（2026-09-16、`:pressed`ルール新規追加分）

「ボタンを押しても見た目が変わらず押した感がない」という要望に対し、`QSpinBox::up-button:pressed`/`QSpinBox::down-button:pressed`に背景色変化ルールを新規追加した修正の確認項目。上記の手順1〜4を再度実施する際、以下の点も併せて確認すること。

1. **最優先**: start_dialog.py・tab2_plot.py（`edit_point_name`）・その他QSpinBox使用箇所の全てで、上ボタン・下ボタンをマウスの左ボタンで押し下げている間（クリック中、ボタンを離す前）、ボタン背景色が変化して見える（押下していない状態と視覚的に区別できる）こと。
2. ボタンを離した後は、押下前の見た目（背景色）に戻ること。
3. ライトモード・ダークモードの双方で、背景色変化が確認できること（`palette(midlight)`参照のためテーマに応じて色が自動追従する設計意図の確認）。ただし配色によっては変化が目視しづらい場合があるため、変化が乏しいと感じた場合はその旨を報告すること。
4. 矢印グリフ（三角形）の表示・位置・クリックによる値の増減自体には影響がないこと（今回の変更は背景色ルールの追加のみで、矢印描画・ボタン位置には触れていない）。

期待される挙動の根拠: 本項目は`.claude/logs/implement/2026-09-16-T-0044-qspinbox-safe-qss.md`の「押下フィードバック追加」セクションに記載の通り、`QSpinBox::up-button:pressed, QSpinBox::down-button:pressed { background-color: palette(midlight); }`ルールを新規追加したことによる。既存の`QSpinBox`本体・`:focus`・`up-button`/`down-button`の`subcontrol-position`・矢印画像参照には変更を加えていない。

### 押下フィードバック方式の転換の確認項目（2026-09-16、背景色→矢印色への切り替え分）

「押下フィードバック追加」以降の3つの背景色系修正（`:pressed`背景色ルール・角丸修正・フォーカス+押下複合セレクタでの`border-left`再宣言）が、フォーカス枠とのオーバーラップやinput全体の背景色崩壊を連鎖的に引き起こしたため、それらを完全に撤去し、矢印SVGアイコン自体の色を押下時に切り替える方式（`::up-arrow:pressed`/`::down-arrow:pressed`）へ転換した修正の確認項目。上記の手順1〜4を再度実施する際、以下の点も併せて確認すること。

1. **最優先**: start_dialog.py・tab2_plot.py（`edit_point_name`）・その他QSpinBox使用箇所の全てで、上ボタン・下ボタンを押し下げている間、**矢印グリフの色**が通常時のニュートラルグレー（`#6B6B6B`相当）から、より濃いグレー（`#404040`相当）へ変化して見えること。ボタンの背景色自体は変化しない（意図的に背景色変化アプローチを廃止したため）。
2. **最優先**: これまで問題となっていた、input（QSpinBox）全体の背景色が崩れる、またはフォーカス時の青いボーダー（`QSpinBox:focus`）に何らかのオーバーラップ・欠けが見える、といった異常が発生していないこと。フォーカス状態と押下状態が同時に起きる場合（フォーカス中のQSpinBoxのボタンを押す）も含めて確認すること。
3. ボタンを離した後は、矢印の色が押下前（ニュートラルグレー）の見た目に戻ること。
4. 矢印の位置・サイズ（8x6px相当）がボタン領域内に収まっており、色が変わる以外の見た目（形状・配置）に変化がないこと。
5. 上下ボタンをクリックした際の値の増減自体（クリック判定領域）に変化がないこと（今回の変更は矢印画像の色切り替えのみで、ボタンのジオメトリ・クリック判定には触れていない）。

期待される挙動の根拠: 本項目は`.claude/logs/implement/2026-09-16-T-0044-qspinbox-safe-qss.md`の「押下フィードバック方式の転換（背景色→矢印色）」セクションに記載の通り、`QSpinBox::up-button:pressed`/`QSpinBox::down-button:pressed`/`QSpinBox:focus::up-button:pressed`/`QSpinBox:focus::down-button:pressed`の背景色系ルールをすべて削除し、代わりに`QSpinBox::up-arrow:pressed`/`QSpinBox::down-arrow:pressed`で`src/icon/spin_up_arrow_pressed.svg`/`spin_down_arrow_pressed.svg`（`fill="#404040"`）を参照するルールを新規追加したことによる。`QSpinBox`本体・`QSpinBox:focus`（ボーダー幅`1.5px`のまま）・`up-button`/`down-button`（非pressed）・通常時の矢印画像参照（非pressed）には変更を加えていない。
