## 人手確認チェックリスト

### 確認手順
1. QGISでプラグインを起動し、セッションを開く（打刻図面が読み込まれた状態にする）。
2. Tab2（デジタイジングタブ）で、モードトグルを「編集」に切り替える。
3. 既存の打点（フィーチャ）にカーソルを近づけてクリックし、選択状態にする（点情報パネルに既存点の属性が表示され、カテゴリウィジェットがロックされることを確認）。
4. 選択した状態のまま、キャンバス上の既存点から離れた「空白」の位置をクリックする（どの既存フィーチャにもスナップしない位置）。
5. 手順4の直後、点情報パネルの表示状態と、モードトグルの状態を確認する。
6. 続けて、モードトグルを「新規」に切り替え、キャンバス上の任意の位置（既存点の近く・空白いずれも）を複数回クリックし、常に新規打点として動作すること（スナップやフィーチャ選択が起きないこと）を確認する。

### 各手順で期待される挙動（設計書ベース）
- 手順3: `src/map_tool.py` の `CanvasDigitizingTool._handle_digitize_click()`（編集モード分岐）の設計により、既存点へのスナップがヒットした場合は `existing_point_selected` シグナルがemitされ、`src/tab2_digitizing_mixin.py` の `_on_existing_point_selected()` がフォームに属性値をロードし、`_set_category_widgets_locked(True)` によりカテゴリウィジェットがロックされる。
- 手順4〜5: 本タスク(T-0039)の実装により、編集モードでのスナップミス（空白クリック）時は `blank_click_in_edit_mode` シグナルがemitされ、`src/main_dock.py` の接続を通じて `Tab2DigitizingMixin._on_blank_click_in_edit_mode()` が呼ばれる。このハンドラは既存の `_reset_point_selection()` を呼び出すため、
  - `selected_edit_point_id` が `None` に戻り、点情報パネルは「新規点作成」の見た目（次の自動連番が反映された点名、枝番クリア等）に戻る
  - カテゴリウィジェットのロックが解除される（`_set_category_widgets_locked(False)`）
  - キャンバス上の選択マーカー（`map_tool.clear_selected_marker()`）が消える
  - 一方で `self.tab2_current_mode` は変更されないため、**モードトグルは「編集」のまま**であること（「新規」に切り替わっていないこと）を目視で確認する
- 手順6: `_handle_digitize_click()` の `mode == "new"` 分岐は本タスクで一切変更していないため、新規モードでは常に `canvas_clicked` がemitされ、既存フィーチャへのスナップ判定自体が行われない（クリック位置に関わらず常に新規打点として振る舞う）という既存(T-0037時点)の挙動に変化がないこと。

### 注意喚起
- `src/main_dock.py` に新規シグナル接続を1行追加した。`MainDockWidget` のシグナル接続はいずれも明示的なdisconnect処理を持たない既存パターンに合わせているため、これ自体は今回のリスクとして目立った差分ではないが、`CanvasDigitizingTool` の生存期間中は常に接続され続ける点は留意。
- `_on_blank_click_in_edit_mode()` は `selected_edit_point_id is None` の場合は早期returnし `_reset_point_selection()` を呼ばない（既に未選択の状態で空白クリックを繰り返しても余計な処理が走らないようにするための軽微な最適化であり、挙動上の意味は変えない設計）。この分岐の要否も含めて目視確認時に違和感がないか留意してほしい。
- 編集モードでの「ヒット時」の挙動（`existing_point_selected` emit、選択マーカー表示等）は本タスクで一切変更していない。手順3で異常があれば、本タスクではなく既存実装（T-0037以前）の問題である可能性が高い。
