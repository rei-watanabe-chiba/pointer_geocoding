## 人手確認チェックリスト

### 対象
`sync_local_edits.bat`（コミットメッセージへの変更ファイル一覧動的追記機能の追加）

### 確認手順
1. Windows実機で、`test`ブランチ（または任意の作業ブランチ）上に未コミットの変更を作る
   （例: 既存ファイルを1つ編集する、または新規ファイルを1つ追加する）。
2. リポジトリ直下で`sync_local_edits.bat`をダブルクリック、または`cmd`から実行する。
3. `choice /c YN /m "Continue"`で`Y`を選択し、処理を進める。
4. スクリプト実行後、生成された`local-edits`ブランチで`git log -1`を実行し、コミットメッセージの
   内容を確認する。
5. コミットメッセージが以下の形式になっていることを確認する。
   - 1行目: `Local edits synced via sync_local_edits.bat (<日時>)`
   - 空行
   - `Changed files:`
   - 手順1で変更した各ファイルが`- <ファイルパス>`の形式で列挙されている
6. `%TEMP%`配下に`sync_local_edits_files_*.txt` / `sync_local_edits_msg_*.txt`という
   一時ファイルが残っていないことを確認する（コミット成功後は自動削除される想定）。
7. （任意）ファイル名にスペースを含むファイルを変更対象に含めた場合も、コミットメッセージ内で
   そのファイル名が欠落・分断されずに1行として正しく表示されることを確認する。

### 各手順で期待される挙動（依頼内容ベース）
- 手順4-5: 依頼内容「コミットメッセージに、実際に変更されたファイルの一覧を動的に追記する」に基づき、
  固定文言+日時の見出し行に加えて`Changed files:`以下に変更ファイル一覧が`- <path>`形式で
  列挙されているべき。これにより、後でコミットメッセージのみを見た別セッションが変更ファイルを
  特定できる状態になっていることを確認する。
- 手順6: 依頼内容「処理完了後、両方の一時ファイルを削除する」に基づき、一時ファイルが
  リポジトリやシステムに残置されていないことを確認する。
- 手順7: 依頼内容「ファイル名にスペースが含まれる可能性を考慮」に基づき、`delims=`指定の
  `for /f`ループでスペース入りファイル名も1行としてそのまま扱われることを確認する。

### 注意喚起
- 本スクリプトは`git commit -m`から`git commit -F <一時ファイル>`への変更を含む。コミットが
  何らかの理由で失敗した場合（例: pre-commit hookでの拒否）、一時ファイル削除後に
  `:commiterror`ラベルへ分岐する経路を通るため、エラーメッセージ表示と`pause`が正しく機能するか
  実機で確認すること。
- 本スクリプトはリモートへの`--force`pushを伴う（既存仕様、今回変更なし）。人手確認時は
  誤って重要なリモートブランチを上書きしないよう、`local-edits`ブランチ専用であることを
  再確認すること。
- Linux環境では本バッチファイルの実行検証ができないため、静的なASCII/CRLF確認・目視によるロジック
  確認のみ実施済みである点に留意すること。
