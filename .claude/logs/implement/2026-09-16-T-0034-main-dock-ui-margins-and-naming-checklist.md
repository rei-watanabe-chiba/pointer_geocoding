## 人手確認チェックリスト

### 確認手順
1. QGISでプラグインをリロードし、点群座標取得パネル（右ドック）を開く。
2. 右ドック上部の4ボタン（画像/設定/出力/保存）の下、常時表示のメイン
   打刻エリア（旧Tab2）との間に、区切り線（横線）が1本表示されていることを
   目視確認する。
3. 画像ボタンをクリックしてダイアログを開き、ダイアログタイトルバー等に
   表示されるタブ名の代わりに設定/出力ダイアログのタイトルを確認する
   （設定ダイアログのタイトルバー文言が「SET」、出力ダイアログのタイトル
   バー文言が「OUT」になっていることを確認）。画像ダイアログ自体は
   `ImageDialog` 専用クラスでタイトル文言の扱いが異なるため、`TAB_1_TITLE`
   ("IMG") がどこに表示されるか（ウィンドウタイトル等）を併せて確認する。
4. 出力ボタンをクリックし、出力ダイアログが正常に開くこと（CSV出力設定
   グループボックス・エンコーディング選択・CSV出力先入力・CSV出力ボタンが
   従来通り表示されること）を確認する。
5. メイン打刻エリア（旧Tab2）の点情報パネル/属性パネル/フォーカスモード
   パネルそれぞれの上端にあるHLine区切り線と、その下のパネル内容との間隔が、
   改修前と比べて狭くなっている（従来の「hr下の余白が広すぎる」という指摘が
   緩和されている）ことを目視確認する。
6. パネル全体の見た目（各パネルの縦間隔、パネル内の行間隔、パネル
   コンテナの左右上下マージン）が、本タスク実施前とおおむね変わっていない
   こと（①③以外は「見た目を変えないリファクタリング」が方針）を確認する。
7. 実際に打刻・既設点編集・CSV出力など一連の操作を行い、レイアウト変更に
   伴うクラッシュや見た目の崩れ（ウィジェットの重なり、はみ出し等）が
   ないことを確認する。

### 各手順で期待される挙動（設計書ベース）
- 手順2: 依頼スコープ「①top_rowとtab2_containerの視覚的区別」の通り、
  `main_dock.py` の `_init_ui()` に `UIStyleHelper.build_separator()` による
  `QFrame(HLine)` を1本追加したため、区切り線が表示されるはず
  （`dcs/integrated_master_design.md` のT-0024節にある「top row of four
  buttons」+「always-visible main digitizing area」という構成に、視覚的な
  区切りを追加する変更）。
- 手順3・4: 依頼スコープ「③タブ名称の表示文字列変更」の通り、
  `UILabels.TAB_3_TITLE` = "SET"、`UILabels.TAB_4_TITLE`（旧
  `OUTPUT_DIALOG_TITLE`）= "OUT" として `ModelessSectionDialog` の
  タイトル引数に渡されるため、各ダイアログのタイトルバーにこの文言が
  表示されるはず。内部処理（`_create_tab4_ui`/`self.tab4_container`への
  リネーム含む）はUI構築のみでロジック変更がないため、出力ダイアログの
  機能自体（CSV出力）は従来通り動作するはず。
- 手順5・6: 依頼スコープ「②余白定数の新設と適用」の通り、区切り線の
  上下だけ `SEPARATOR_MARGIN_TOP`/`SEPARATOR_MARGIN_BOTTOM`
  （初期値: 各4px、旧`PANEL_GROUP_SPACING`=8の半分）に分離し、他の
  マージン・スペーシング定数（`PANEL_CONTAINER_MARGIN_*`,
  `PANEL_GROUP_SPACING`, `PANEL_INNER_SPACING`等）は旧ハードコード値を
  そのまま踏襲しているため、区切り線直下の余白のみ狭くなり、それ以外の
  見た目は変化しないはず。
- 手順7: 本タスクはUI/表示のみの変更でロジック（信号接続・打刻/編集/CSV
  出力処理そのもの）は変更していないため、既存の操作フローが壊れていない
  ことの確認。

### 注意喚起
- `layout.addSpacing()` をレイアウトに複数箇所追加する変更は、Qtの
  QVBoxLayoutにおいてウィジェット非表示（`.hide()`）時の余白の挙動に
  影響する可能性がある。本タスクで触れた区切り線自体は常時表示ウィジェット
  だが、`tab2_digitizing_mixin.py` には他にも `.hide()`/`.show()` される
  ウィジェット（`row_existing_actions`, `edit_point_name_sp` 等）が同じ
  `layout`/`info_layout` 内に存在するため、既設点編集⇔新規点作成の切り替え時に
  余白の見え方が変化していないか、手順7の一連の操作の中で併せて確認すること。
- `main_dock_constants.py` の `PANEL_CONTAINER_MARGIN_LEFT/TOP/RIGHT/BOTTOM`
  は依頼文の「PANEL_CONTAINER_MARGIN_LR/TB」という4定数案から、既存コメント
  （右マージンのみスクロールバー避けで非対称）の意図を保つため実装時に
  4つの独立定数（LEFT/TOP/RIGHT/BOTTOM）へ変更している。将来この定数を
  参照するコードを追加する際は、この命名（LR/TBではなくLEFT/TOP/RIGHT/
  BOTTOM）である点に注意すること。
